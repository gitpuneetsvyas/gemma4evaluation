## Summary of Hexagonal Flow

1. **Web Layer (Request):** An HTTP POST request hits `/deposit`.
2. **Application Layer (Entry Point):** The Controller maps the request to [K
`DepositAccountCommand`.
3. **Application Layer (Handler):** The `DepositAccountHandler` validates t[1D[K
the command and calls the domain.
4. **Domain Layer (Service):** The `AccountService` executes business rules[5D[K
rules, resulting in an invariant change and generating a `Transaction` even[4D[K
event.
5. **Application Layer (Event Store Port):** The handler calls `eventStore.[12D[K
`eventStore.save(transaction)` (the Port).
6. **Infrastructure Layer (Adapter):** The `MongoEventStoreAdapter` (the Ad[2D[K
Adapter) receives the event and persists it to MongoDB.
7. **Result:** The operation is completed, ensuring the core business logic[5D[K
logic (Domain) is completely isolated from the persistence details (Infrast[8D[K
(Infrastructure).
