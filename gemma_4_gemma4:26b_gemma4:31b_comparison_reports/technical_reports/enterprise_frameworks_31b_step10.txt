The core strategy is to decouple the frameworks via a **Standardized Commun[6D[K
Communication Plane**.

*   **The North-South Plane:** Managed by **Kong API Gateway** and **Istio*[8D[K
**Istio**, handling ingress, security, and traffic shaping.
*   **The East-West Plane:** Managed by **gRPC** for synchronous low-latenc[10D[K
low-latency calls and **Apache Kafka** for asynchronous event-driven commun[6D[K
communication.
*   **The Identity Plane:** Centralized **OIDC/OAuth2** (via Okta or Azure [K

*   **The Observability Plane:** OpenTelemetry (OTel) exporting to Promethe[8D[K
Prometheus/Grafana and Jaeger.

# 5. Cross-Cutting Enterprise Concerns

### Security Implementation (Zero Trust)
Every service implementation follows this security chain:
1. **Identity:** All requests must carry a JWT issued by the corporate IdP.[4D[K
IdP.
2. **Validation:** The API Gateway validates the signature; the individ[7D[K
individual service validates the `scopes` and `permissions` (RBAC).
3. **mTLS:** Istio enforces mutual TLS for all service-to-service communica[9D[K
communication, ensuring that a compromised pod cannot sniff traffic.

### Database Integration Pattern (Polyglot Persistence)
We implement **CQRS (Command Query Responsibility Segregation)**:
- **Write Side:** Relational databases (PostgreSQL/SQL Server) for ACID com[3D[K
compliance.
- **Read Side:** ElasticSearch or MongoDB for high-speed retrieval and full[4D[K
full-text search.
- **Sync:** Kafka Connect streams updates from the Write DB to the Read DB.[3D[K
DB.

### Monitoring & Observability
We standardize on **OpenTelemetry**:
- **Tracing:** Every request is injected with a `trace-id` at the Kong Gate[4D[K
Gateway. This ID propagates through Java $\rightarrow$ Go $\rightarrow$ Pyt[3D[K
Python.
- **Metrics:** All frameworks export metrics in Prometheus format (`/metric[9D[K
(`/metrics` endpoint).
- **Logging:** Structured JSON logs are shipped via FluentBit to an ELK/Spl[7D[K
ELK/Splunk cluster.
