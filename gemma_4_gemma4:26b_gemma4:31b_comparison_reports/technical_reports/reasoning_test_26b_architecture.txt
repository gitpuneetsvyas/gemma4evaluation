# 3. MIGRATION STRATEGY (24-MONTH TIMELINE)

**The Strangler Fig Strategy:** We will wrap the legacy monolith with an AP[2D[K
API Gateway and slowly peel away functionalities.

### Phase 1: Foundation (0-6 Months)
*   Establish Multi-region Cloud Landing Zone.
*   Deploy API Gateway in front of the Legacy Monolith.
*   Implement **CDC (Change Data Capture)** using **Debezium** on Oracle 11[2D[K
11g to stream data changes to Kafka.
*   Deploy Identity Service (The first microservice) to decouple Authentica[10D[K
Authentication.

### Phase 2: Read-Heavy Services (6-12 Months)
*   Migrate Catalog and Search to new microservices.
*   Use the "Sidecar" pattern to sync Oracle data to Elasticsearch.
*   **Goal:** Reduce load on the legacy Oracle DB by offloading 70% of read[4D[K
read traffic to new microservices.

### Phase 3: Transactional Services (12-18 Months)
*   Migrate Order and Inventory.
*   **Dual-Write Pattern:** During transition, the API Gateway routes write[5D[K
writes to both the new Microservice and the Legacy Monolith to ensure data [K
consistency.
*   Implement Distributed Transactions using the **Saga Pattern** (Orchestr[9D[K
(Orchestration-based).

### Phase 4: Ecosystem & Intelligence (18-24 Months)
*   Decommission the Monolith.
*   Deploy ML-driven Personalization engines (SageMaker).
*   Integrate 200+ partners via a standardized Event-driven API Catalog.
